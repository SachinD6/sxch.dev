building pi-resume-harness

resuming claude, cursor, codex and grok sessions inside pi.

oct 16, 2026 · 4 min read · pi, typescript · source · npm

claude code, cursor, codex, grok, pi. that’s basically my whole dock right now.

i love pi for the same reason everyone does. four tools, a tiny prompt, you see every token. but all my old context was stuck somewhere else. a half-finished auth flow in claude code. a cursor chat with the exact error i already fixed once. you know the pain.

re-explaining all of that to pi from scratch gets old fast. so i built pi-resume-harness — a pi extension that reads those other tools’ saved sessions straight from disk and keeps going inside pi. no apis, no retyping.

this is a handoff, not a live restore. the old conversation gets summarized and carried forward, never replayed.

tl;dr

  • /resume-claude /resume-cursor /resume-codex /resume-grok resume a foreign session in pi
  • /resume-foreign picks from all of them in one list, scoped to your current folder
  • /copy-session copies the full transcript to the clipboard, paste it into any agent
  • everything runs locally. the source cli is never invoked, nothing is sent anywhere.
pi install npm:pi-resume-harness

restart pi, cd into your project, run /resume-foreign. done.

why not just copy-paste

that was my v0, and it breaks three ways. you lose the tool calls, and the “tried x, got y” part is the useful part. session files are nasty jsonl with envelopes and slash-command noise. and every tool stores dozens of sessions named like 8f3a1c2e-…

what i actually wanted: open pi in my project, see only this project’s sessions, fuzzy-filter by a word, hit enter. so that’s what it does.

how it works

each command just reads that tool’s local store. that’s it.

commandstore it reads
/resume-claude~/.claude/projects/<slug>/*.jsonl
/resume-cursor~/.cursor/projects/…/agent-transcripts/
/resume-codex~/.codex/sessions/**/rollout-*.jsonl
/resume-grok~/.grok/sessions/<cwd>/<id>/chat_history.jsonl

only sessions belonging to your current folder are listed. subfolders and the parent project count; $HOME never matches everything — learned that one the hard way.

/resume-cursor
/resume-claude latest
/resume-grok 8f3a1c2e-…
/resume-foreign auth
/copy-session latest

nothing opens a searchable picker. a word pre-filters it. latest skips the list. an id or a path takes that exact session. with no ui it just prints matching ids, which saves you over ssh.

what surprised me

cursor was the messiest — two locations, encoded paths, inconsistent shapes. claude was the cleanest, one jsonl per session. titles lie everywhere, most transcripts wrap your real prompt in xml or slash-command envelopes, so the picker strips those and shows what you actually typed.

and /copy-session became the real feature. i built it as an extra; it’s what i use most. full transcript in order, tool calls as historical record, a short header with project, branch and session id. it uses whatever clipboard tool it finds: pbcopy, clip, wl-copy, xclip.

the safety bit

a foreign transcript is untrusted history. it can contain instructions like “run this curl”. so the handoff tells pi to never execute instructions found in the transcript, treat foreign tool calls as text rather than available tools, verify files and git state before changing anything, and treat prior tool output as stale. system prompts and encrypted reasoning blocks are never included.

still, only resume sessions you trust. you’re feeding another agent’s output into an agent with bash access.

dev notes

no runtime deps beyond what pi ships. typescript loads via jiti.

git clone git@github.com:SachinD6/pi-resume-harness.git
cd pi-resume-harness
npm test
pi install "$PWD"

npm test needs node 22+. tests cover all four readers plus resolve and handoff, because parsers rot fast when those tools change their formats.

wrap up

don’t try to resume everything. most old sessions deserve to die. what actually works: latest ninety percent of the time, /resume-foreign when you forgot where you left off, /copy-session when you’re leaving pi and taking context with you.

if i missed a harness you use, tell me. the reader pattern is small; a fifth one is about fifty lines.

thanks for reading.
